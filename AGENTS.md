# Правила QwenDirector

Работаем как ведущий JS/TS-разработчик проекта justlovejazz: цель — автономная local-first среда для 3D, image, video и sound. Лаборатория: два Proxmox-кластера, 2× RTX 4060 Ti и RTX 5090, Ubuntu 26 + Sway, VM macOS. Это пользовательский контекст, а не подтверждённая инвентаризация.

- Начинай с [README](README.md) и [next-session](docs/next-session.md); проверяй содержимое и изменения перед записью. Сохраняй пользовательские файлы и служебные каталоги.
- Документация — на русском, идентификаторы кода — на английском. При изменении архитектуры обновляй ADR и контракт.
- TypeScript: Vue 3/Vite, Node.js/Fastify. Python допустим как тонкий адаптер. Перед работой с TresJS изучи доступный skill `tresjs`.
- Никаких облачных вызовов, телеметрии и внешних провайдеров по умолчанию. Не публикуй и не отправляй данные наружу без явного разрешения.
- Не устанавливай тяжёлые зависимости, не скачивай модели и не запускай внешние сервисы без соответствующей задачи. Не выводи секреты. `.env`, ассеты и данные лаборатории не коммитить.
- Не меняй Proxmox, GPU passthrough, драйверы, сетевые правила и данные узлов в рамках обычной разработки. Сначала подготовь конкретный план изменения.
- API/UI работают с логическими ресурсами, а не адресами GPU. Адаптеры не записывают напрямую в БД.
- С первого MVP: persistent jobs, attempt/lease/fencing, идемпотентность, отмена, provenance, immutable input snapshots и ручные утверждения. Повторная доставка допустима; повторное принятие результата — нет.
- Используй mock-исполнитель до реальной GPU-интеграции. Проверяй существенные сценарии отказов, а не только успешный запуск.
- Не копируй код Director Studio до проверки точного репозитория, commit и лицензии. Сходство интерфейса не подтверждает совместимость архитектуры.
- Завершая сессию, обнови [next-session](docs/next-session.md): сделанное, ограничения, следующие команды и результаты проверок. Не объявляй каркас работающим продуктом.

## Локальные image edits и экранный композит

- Считай Qwen Image edit полноформатной перегенерацией, пока конкретный workflow graph не доказывает локализацию через корректную маску. Текст промпта сам по себе не ограничивает область изменения.
- Перед локальной правкой проверь revision/hash графа, входы и роли, размеры изображения и маски, их pixel/latent semantics, способ ресайза и composite path. Кратность холста 32 — требование некоторых latent-тензоров, но не доказательство корректности маски или локального редактирования.
- Для точных обложек, экранов, этикеток и других плоских деталей предпочитай отдельный слой/перспективный композит с сохранением исходника и provenance. Не запускай повторный full-frame edit для вставки содержимого в известную плоскость.
- Перед повторным применением mask graph сделай один изолированный тест и сравни пиксели вне маски с исходником. При глобальной утечке текстуры/цвета или поломке кадра отклони результат, зафиксируй lineage и останови этот граф; не пытайся лечить его только переформулировкой промпта.
- Для физического экрана сначала используй установленную геометрию blank plate: corner-pin/perspective insert по четырём углам, маска рамки, затем умеренное согласование яркости, отражений и цвета. Проверь экран с точки зрения камеры и внешнего зрителя. Если плоскость/углы неразличимы, сначала получи пригодный plate, а не перегенерируй всю комнату.
- Перед production-generation проверяй immutable job snapshot: роли и ID реальных image references, число входов, выбранный профиль/mode и graph bindings. Текстовые упоминания `Picture 1/2` не подключают изображения; если промпт требует референс, job без приложенных image assets блокируется. Не оценивать identity/prop consistency по prompt или preflight — только по реальному output.
- Для Qwen Image 2.1 учитывай фактический контракт ComfyUI `/object_info`: `TextEncodeQwenImage21` output 2 — пустой latent заданного reference-размера, не кодировка base image. Image-edit должен кодировать первый `LoadImage` через `VAELoader` + `VAEEncode` либо локализованный `VAEEncodeForInpaint`, а `KSampler.latent_image` должен получать соответствующий base latent; для `VAEEncodeForInpaint` маска обязана быть соединена с тем же base image через проверенный mask path. Schema pass и наличие `Picture 1/2` не доказывают сохранение исходного кадра; если sampler стартует с пустого/encoder latent, отклони профиль до production. Кратность 32 сама по себе не исправляет wiring.
- Для Qwen Image 2.1 `VAEEncodeForInpaint` с `ImageColorToMask` может пройти schema/runtime preflight, но вернуть плоскую серую область вместо дорисованного содержимого. Проверяй реальный PNG после каждой новой масочной связки; до визуального pass профиль не считать рабочим, кадр не выбирать и не отправлять этот graph на повтор без изменения причины.
- Для MiniMax H3 Ref2VA локальный тест THE LAST RECORD выявил две ошибки: multi-reference профиль может вывести сами reference images как содержимое ролика, а push-in из wide кадра с целым велосипедистом может сохранить героя вдали и добавить его же крупно с велосипедом на переднем плане. Пока иное поведение конкретного графа не доказано реальным тестом, не считай multi-reference набор невидимыми identity anchors; один continuity frame тоже не гарантирует отсутствие дублей при push-in. Сначала задай нужную крупность в отдельном keyframe или делай самостоятельный cutaway, затем генерируй одну простую action chain. Просматривай весь take от первого до последнего кадра: отклоняй вспышку ref-фото, второго человека/велосипед, двойные руки и одновременный wide+close того же героя; не выбирай output только по хорошей середине.

# Правила QwenDirector

Работаем как ведущий JS/TS-разработчик проекта justlovejazz: цель — автономная local-first среда для 3D, image, video и sound. Лаборатория: два Proxmox-кластера, 2× RTX 4060 Ti и RTX 5090, Ubuntu 26 + Sway, VM macOS. Это пользовательский контекст, а не подтверждённая инвентаризация.

- Начинай с [README](README.md) и [next-session](docs/next-session.md); проверяй содержимое и изменения перед записью. Сохраняй пользовательские файлы и служебные каталоги.
- Документация — на русском, идентификаторы кода — на английском. При изменении архитектуры обновляй ADR и контракт.
- TypeScript: Vue 3/Vite, Node.js/Fastify. Python допустим как тонкий адаптер. Перед работой с TresJS изучи доступный skill `tresjs`.
- Никаких облачных вызовов, телеметрии и внешних провайдеров по умолчанию. Не публикуй и не отправляй данные наружу без явного разрешения.
- Не устанавливай тяжёлые зависимости, не скачивай модели и не запускай внешние сервисы без соответствующей задачи. Не выводи секреты. `.env`, ассеты и данные лаборатории не коммитить.
- Не меняй Proxmox, GPU passthrough, драйверы, сетевые правила и данные узлов в рамках обычной разработки. Сначала подготовь конкретный план изменения.
- API/UI работают с логическими ресурсами, а не адресами GPU. Адаптеры не записывают напрямую в БД.
- С первого MVP: persistent jobs, attempt/lease/fencing, идемпотентность, отмена, provenance, immutable input snapshots и ручные утверждения. Повторная доставка допустима; повторное принятие результата — нет.
- Используй mock-исполнитель до реальной GPU-интеграции. Проверяй существенные сценарии отказов, а не только успешный запуск.
- Не копируй код Director Studio до проверки точного репозитория, commit и лицензии. Сходство интерфейса не подтверждает совместимость архитектуры.
- Завершая сессию, обнови [next-session](docs/next-session.md): сделанное, ограничения, следующие команды и результаты проверок. Не объявляй каркас работающим продуктом.

# Storyboard-first production flow — текущий gate

**Статус:** production planning остановлен до текстового утверждения. Старые episode IDs, prompts, asset choices, handoff plans и storyboard layout ниже не наследуются. Этот документ задаёт только следующий порядок после согласования сценария; ни одна иллюстрация/генерация в этом проходе не запускалась.

## До storyboard lock

1. Утвердить причинность и финальную версию в `05-screenplay-draft.md`, а не только общую тему.
2. Пользователь читает и правит актуальный screenplay. Сюжетные решения о личной доставке, доверии DJ, его уходе из сцены, non-diegetic master и ответственности героя за зал уже подтверждены. До storyboard остаются реальные площадки/география, blocking ухода DJ и visual-score arc.
3. Подтвердить референсы: character sheets и новые refmods должны быть созданы заново из проверенных источников, отдельно для героя, DJ, велосипеда, пластинки и локаций. Пользовательский велосипед `references/photo/fixedgear-bike.jpeg` остаётся авторитетным для компонентов.
4. Проверить актуальный Qwen Image 2.1 workflow для текстовых и reference-based кадров, размеры/crop/32-grid и фактические входные роли. Для разрешения ориентироваться на реальный workflow, а не на старые 1376×768/1024 параметры из архивных job пакетов.

## После утверждения текста

1. Создать scene boards по актам, каждый кадр точно отвечает действию в сценарии.
2. На каждом листе варьировать крупность и высоту камеры по новой информации: establish, master, medium, close, detail, reaction; не создавать повтор ракурса ради заполнения сетки.
3. Для каждого кадра фиксировать stable ID, audio candidate window, действие/старт-конец, ось/экранный вектор, мотивированное движение, focus plane/ГРИП, практический источник, предполагаемую склейку и QC-критерий.
4. Держать мастер непрерывным и неизменным. Кандидатные музыкальные границы сверять в NLE; lyric timing/downbeat пока не выдумывать.
5. Проверять boards как соседние планы и причинную последовательность. Затем обновить shot bible и только после отдельного production decision готовить Qwen/H3 prompt package.

## Производственные ограничения

- Qwen Image stills не считаются готовыми кадрами клипа; H3 source generation 5–8 s может дать монтажные фрагменты 2–4 s, это разные длительности.
- Один H3 prompt — одно доминирующее физическое действие; handoff, лица, руки, игла и crowd response снимаются отдельным покрытием.
- Для толпы использовать малые группы/раздельные реакции и разные фазовые действия; не просить большую группу двигаться синхронно.
- Ночная ГРИП выбирается по функции: фон мягче только когда география уже понятна; лицо и действие должны оставаться читаемыми.
- Перед любым batch заново сверить `/ready`, worker/queue, `COMFYUI_URL`, workflow mode/revision/hash, input roles, runtime schema и параметры. Сохранять immutable job snapshots, manual approval, lease/fencing, CAS и provenance; не отправлять прямые ComfyUI jobs.

## Устаревшие технические детали

Любые указания в старых production files запускать S04–S07 первыми, собирать 4–8 frames на эпизод, использовать profile/hash `last-record-qwen-image21-keyframe-16x9-v1` или следовать LR-S01–LR-S08 из отвергнутой версии — исторические. Новый storyboard cadence, профили и размеры выводятся из утверждённого сценария и свежего preflight.

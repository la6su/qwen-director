# Режиссёрские подсказки и MiniMax H3

Этот документ переносит в QwenDirector рабочие идеи локального `minimax-h3-director` skill и проверенные свойства MiniMax H3. Это методические подсказки, а не обещание качества модели и не строгая спецификация ComfyUI.

## Что подтверждено реализацией

- H3 работает с 24 fps и кадрами на сетке `17k + 5`; например, 124 кадра — 5.17 секунды. QwenDirector округляет введённую длительность вверх до ближайшей точки этой сетки.
- Диапазон 124–362 кадра описан официальным H3 узлом как обученный диапазон. Это ориентир: корректная сетка за диапазоном сама по себе не гарантирует качество.
- У официального `MiniMaxH3ImageToVideo` входы first/last frame задают режим по наличию изображений; `MiniMaxH3ReferenceToVideo` принимает размеченные визуальные/аудио/видео references.
- Поля H3 промпта остаются обычным текстом. Шесть заголовков Ref2VA, которые формирует контракт QwenDirector, — наша договорённость для ясности и повторяемости, а не схема, валидируемая ComfyUI.

Эти утверждения проверяются по установленной версии ComfyUI и локальному узлу; они не привязывают проект к стороннему Director plugin.

## Сборка Ref2VA промпта

Для H3 Ref2VA QwenDirector формирует шесть блоков: `subject_definitions`, `summary`, `retention_analysis`, `detailed_description`, `overall_soundscape`, `non_diegetic_music`. Каждый подключённый reference получает отдельную метку (`<Picture N>`, `<Video N>`, `<Audio N>`) и одну ограниченную роль. Скомпилированный prompt включается в immutable snapshot; визуальный brief не подменяется выдуманными подробностями ассетов.

Soundscape и музыка разделены. При пустом поле музыки записывается `N/A`; для пустого саундскейпа задаётся только сдержанная локационная атмосфера и Foley без незапрошенной речи. Для остальных workflow остаётся общий компилятор.

## Монтажные проверки

Перед storyboard, монтажной картой и последовательным generation выполняется обязательный попарный аудит соседних кадров по [Cinematic Editing & Keyframe Continuity](../.agents/skills/music-video-camera-direction/references/cinematic-editing-keyframe-continuity.md). Каждая проверка получает статус `PASS`, `INTENTIONAL BREAK` с причиной или `UNVERIFIED`; нарушение не маскируется молча. Планировщик может предложить проверить размер плана, смену угла, ось, направление движения, фазу действия, фокус внимания, свет/цвет и мотивированность перехода. Числа из пользовательской версии правил (например, 30°, 1/3 кадра и 2–3 кадра у музыкального акцента) используются как стартовые монтажные ориентиры, не как независимо подтверждённые универсальные законы.

## Операторская грамматика сложного движения

Для съёмочных crane/jib, robot-arm, drone/aerial, slider/dolly-on-rails и их виртуальной имитации в AI shot планах действует отдельный локальный skill: [`.agents/skills/music-video-camera-direction/SKILL.md`](../.agents/skills/music-video-camera-direction/SKILL.md). Он требует сначала назвать драматическую функцию и пространственные ориентиры, затем задать путь камеры, темп/ускорение/торможение, параллакс, фокус и монтажную точку.

Сложные проходы не запрещены: у каждого есть один основной путь и только те дополнительные оси, которые открывают новое действие/пространство/изменение внимания. Например: боковой slider плюс небольшой pan, crane rise плюс tilt, drone-style glide плюс медленный yaw, robot-arm arc с точной остановкой на предмете. Если такое движение нельзя удержать в одном H3 take без потери геометрии или действия, разобрать его на покрытие и собрать впечатление сложного движения склейками. Не добавлять эффекты ради списка оборудования; аппаратные названия описывают визуальную траекторию и не обещают наличия реального рига или моделированной физики в workflow.

QC проверяет фактическое движение по всему take: start/middle/peak/end, параллакс и геометрию, предметные/персонажные инварианты, ось/вектор и пригодность handles. Один удачный кадр не подтверждает качество траектории.

Точные формулировки книг Соколова и Медынского проектно не верифицированы по сканам/страницам. Чек-лист фиксирует переданный пользователем метод и числа как рабочую конвенцию этого проекта; он не заявляет академическую цитатную точность.

## Референсный ComfyUI плагин

`AIMixer/ComfyUI_MiniMaxH3_Director` уже установлен в лабораторном ComfyUI checkout на commit `4c6245e518dd8a494f3afc4f3cccd53f22d82d10` (Apache-2.0). На момент проверки upstream `main` указывал на `85c66f59d6b13bec71324271258fcae07a2a5898`, то есть локальная установка отстаёт. README upstream описывает сегментную шкалу времени, группы reference с локальными и общими материалами, выборочное выполнение, отчёт по сегментам и опциональную передачу хвоста контекста. QwenDirector остаётся владельцем durable jobs, approvals, immutable snapshots и provenance; плагины расширяют Comfy graph, но не являются управляющим API QwenDirector.

Semantic Bridge, SelfLift и sampler continuity-патчи не включаются автоматически. Это опциональные изменения траектории генерации с отдельными весами/режимами, которые требуют независимого quality-сравнения на выбранном пользовательском baseline. Текущий provisional baseline остаётся стандартным Ref2V INT8 pruned + Pika Flex; выбор не фиксируется как финальный продуктовый default.

## Draft → optional local finish

Драфт и Open-H3 finish — два отдельных решения. Сначала утверждается композиция, субъект, фаза движения и монтажный выход драфта; только затем выбранный клип попадает во второй генеративный проход. Open-H3 Regenerate может прорисовать поверхность детальнее, но также изменить идентичность, одежду, надписи или предметные инварианты. Для клиентских интерьеров и брендовых деталей оставляем ветку без Regenerate; качество finish-пути подтверждается покадровым A/B.

Промежуточный refined latent сохраняется перед VAE decode для восстановления после ошибки decode. Такое сохранение не гарантирует меньший peak VRAM. Различие режимов, sigma и измерительный план зафиксированы в [лаборатории оптимизации](h3-optimization-lab.md); 2K-финиш не входит в default profile.

## Локальный `MiniMax+H3+Director.json`

Проверен пользовательский ComfyUI UI-граф с plugin-нодой `MiniMaxH3Director`, четырьмя последовательными сегментами (три по 362 и последний 124 кадра: 1210 кадров / 24 fps ≈ 50.42 секунды), общими reference slots и включённым 22-frame context handoff. Активный model stack в графе — hybrid `minimax_h3_hybrid_fl2va_ref2va_b20-49-int8.safetensors` плюс `minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors`; это другой экспериментальный профиль, чем Ref2V INT8 pruned + Pika Flex.

Текущий QwenDirector workflow converter превращал UI-граф в API graph, но сдвигал числовые/enum widget values после изменившейся схемы plugin node. Проверка с live `/object_info` нашла неверные типы у `frame_rate`, `timeline_data`, `steps`, `shift_video`, `export_source_images`; поэтому включена строгая валидация литералов и enum choices. Теперь этот stale graph корректно отклоняется до активации вместо молчаливого изменения значений. Профиль также не проходит H3 boundary, потому что QwenDirector пока поддерживает native H3 node, а не plugin `MiniMaxH3Director` boundary.

На момент проверки семь уникальных image references из сохранённого plugin timeline отсутствуют в ComfyUI input API (`/view`, type=input). Значит, даже после адаптации node boundary их потребуется импортировать в QwenDirector как AssetVersion и заново связать с timeline; локальные filename references не удовлетворяют provenance контракту. Следующий интеграционный шаг — versioned AIMixer boundary/importer для сегментов и reference remapping, затем DB snapshot/preflight. Сам файл не изменялся, в очередь ничего не ставилось.
